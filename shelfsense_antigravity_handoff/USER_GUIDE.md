# ShelfSense AI — Planogram Designer User Guide (MVP target)

> This guide describes the intended first-stage workflow. Once Antigravity implements the app, update the setup commands and screenshots to match the actual repository and verify every step.

## What this version does

The first version is a local inventory/planogram editor. You can maintain a product catalogue, create one or more shelf objects, arrange products on shelf rows, save the planogram, and export its visual representation plus a JSON representation with real dimensions. It does not yet inspect live shelf photos or run YOLO/CLIP/OCR.

## Start the application

The final repository should document exact commands in its README. Expected local setup will be similar to:

1. Install supported Python and Node.js versions listed in the repository README.
2. In one terminal, create/activate a Python virtual environment, install backend dependencies, and start FastAPI.
3. In another terminal, install frontend dependencies and start Next.js.
4. Open the local frontend URL printed by the dev server. Confirm the backend health endpoint responds.

Use the exact commands generated by the implementation; do not assume default ports if the README specifies different ones.

## Dashboard

- Review totals calculated from your actual local database.
- Select **Create Planogram** to start a new layout.
- Open a saved planogram from the recent plans list to continue editing.
- If the database is empty, use the Create action rather than expecting fictional activity or analytics.

## Create products

1. Open **Design Your Own Planogram** and choose **Add Product**.
2. Upload a front-facing product image or select a seeded sample product.
3. Enter a unique SKU, product name, width, height, depth in cm, price and currency.
4. Review the preview and verify the measurements before saving.
5. Find the saved product in Product Library. It should remain available after refreshing the app.

The bundled demo items use invented dimensions/prices to show editor behavior; replace these with verified manufacturer or measured values for real plans.

## Create and configure shelves

1. Start with the initially empty canvas and click **Add Shelf**.
2. Select the new shelf in the scene tree or canvas.
3. Edit its name, width, total height, depth and number of rows.
4. Toggle the bottom plinth/base header if needed and enter its height.
5. Check the dimension labels on the bright shelf canvas. The drawing may be scaled to fit but the labels should report the actual physical values.
6. Add additional shelves if the plan requires separate shelf units.

When reducing row count, the application should protect existing placements and warn before any operation that would remove a populated row.

## Place and arrange products

1. Drag a product from Product Library to a shelf row. If drag/drop is unavailable on your device, use the product's **Add to Shelf** action.
2. Drop a product again to add another facing.
3. Move products between rows or reorder them horizontally.
4. Check the row capacity indicator and product dimensions. A product must not overlap another product or exceed the usable row width.
5. If the application refuses a placement, read the message and either choose a wider shelf, use a narrower product, or move items to another row.
6. Select a placement to view its product and position details in the Properties panel.

## Save and reopen

1. Give the planogram a clear name and click **Save**.
2. Wait for the app to confirm **Saved**. If it shows a save error, do not assume the changes were stored.
3. Return to Dashboard and open the saved planogram.
4. Refresh the browser and, for a persistence check, restart the local app. The saved arrangement should reload from SQLite and image files on disk.

## Export

- Use **Export visual** to download a clean shelf graphic with product placements, shelf name and physical measurements.
- Use **Export JSON** to download a structured reference file. Check that it contains the planogram name, `format_version`, units, shelf dimensions, row information, product SKUs and placement coordinates in centimetres.
- Keep the JSON as the future reference input for the shelf-compliance pipeline.

## Data and limitations

- The app is local-first; SQLite and local image files are the source of persistence. Back up both before deleting project data.
- Do not commit the local database, uploaded user images, `.env` secrets or generated build output to Git.
- The 2D canvas is a planning view, not a manufacturing CAD tool. Product/shelf dimensions must be verified before using a layout operationally.
- Computer vision, price-label OCR, automatic compliance scoring, user accounts and cloud synchronization are not part of this MVP.
