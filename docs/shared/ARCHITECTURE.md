## 2. Core Architectural Invariants

1. **Physical Centimetres over Pixels**:
   All database models, validation rules, collision math, and export JSONs strictly store and compute dimensions in physical centimetres (`cm`). Frontend pixels (`px`) are strictly a local viewport projection scale.
2. **Strict Bounds & Collision Math**:
   Products placed on a shelf row cannot exceed the usable row width ($\sum \text{width} \le \text{Shelf Width}$) and cannot overlap adjacent placements on the same row ($X_{\text{start}, i+1} \ge X_{\text{start}, i} + \text{Width}_i$).
3. **No Mock Persistence**:
   SQLite (`backend/shelfsense.db`) and local disk storage (`backend/uploads/`) represent the sole ground truth. Client states must always hydrate from and sync to the backend API.
4. **Vector Semantics via CLIP**:
   Every catalog product maintains an $L_2$-normalized 512-dimensional vector embedding generated by OpenCLIP (`ViT-B/32`). This allows semantic similarity search, automatic pack clustering, and visual compliance checks.

## 3. Component Deep Dive

### A. Frontend (`frontend/`)
- **Framework**: Next.js 14 (App Router) + TypeScript + Tailwind CSS + Lucide Icons.
- **Canvas Rendering**: Pure responsive SVG/HTML5 canvas with interactive drag-and-drop, collision snapping, and measurement brackets.
- **State Management**: React hooks paired with direct REST synchronization (`frontend/src/lib/api.ts`).
- **Telemetry**: `frontend/src/lib/logger.ts` dispatches fire-and-forget UI actions to `POST /api/v1/logs/event`.

### B. Backend (`backend/`)
- **Framework**: FastAPI + Pydantic v2 + SQLAlchemy ORM.
- **Database**: SQLite with dynamic PRAGMA column auto-migration (`init_db()`).
- **Endpoints**:
  - `/api/v1/products`: Product CRUD with image upload and automatic CLIP embedding.
  - `/api/v1/planograms`: Planogram creation, duplication, deletion, and placement management.
  - `/api/v1/logs/event`: Client event ingestion endpoint.
  - `/health`: Uptime, database health, and storage accessibility status.

### C. ML & Embedding Pipeline
- **Engine**: `open-clip-torch` running `ViT-B-32-quickgelu` with OpenAI weights (`backend/app/services/embedding_service.py`).
- **Inference**: High-speed CPU inference (~40ms per image), thread-safe singleton, cached in `~/.cache/huggingface/`.
- **Database Column**: Stored as a raw 512-float JSON array on the `products` table.

### D. Unified Logging Pipeline (`logs/`)
- **Central File**: `logs/logs.txt` gathers Frontend actions, Backend HTTP requests, and Background Worker telemetry in chronological order.
- **Monitor Tool**: `logs/log_collector.py` provides color-coded live streaming (`--follow`), background job filtering (`--jobs`), and summary metrics (`--summary`).
